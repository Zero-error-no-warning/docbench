# DocBench の画面設計

業務用の書類作成・様式編集ツールとして、操作の目的と編集中の対象を読み取れることを優先する。

## 根拠と適用範囲

UI/UX Pro Max の公式リポジトリの SKILL.md、quick-reference.md と検索データを参照した。
出典: https://github.com/nextlevelbuilder/ui-ux-pro-max-skill

- `document editor enterprise productivity --design-system --variance 2 --density 7`：Minimalism & Swiss Style を採用。生成された販売用ランディングページの構成は編集画面には適用しない。
- `productivity document editor --domain product`：Productivity Tool の「明確な階層と機能に対応する色」を採用。
- 検索で得たフォーム規則と quick-reference の可視階層、キーボード、選択状態、可読性、コンテンツ優先順位を実画面へ適用する。

実装は既存の HTML / CSS / JavaScript を使う。実行時の CDN・Web フォント・新しいフレームワークは追加しない。

## 表示の階層

1. 工程：薄いグレーのナビゲーション。工程名に短い目的の説明を付ける。
2. 対象：一覧を薄いグレー、設定欄を白で区別。現在選んでいる名前を設定欄の上部に明示する。
3. 主操作：項目追加・検証・出力など、その場所の主操作に青を使う。保存・履歴などの共通操作は控えめにする。
4. 結果：プレビューの作業面は薄いグレー。フォームはセクションごとに白い面でまとめる。
5. 詳細：キー・内部型・補足は二次情報。必須・エラーは文字と色を併用する。

## 作業領域の構成

- 初期表示は「対象を選ぶ一覧」と「選んだ対象の設定」を同じ左側の領域で切り替える。右側のフォーム・型プレビュー、条件キャンバスは別の作業面として維持する。
- 一覧では検索・階層の展開・項目追加を行う。項目の選択と新規追加は設定画面を開く。戻る操作はDOMの再生成をせず、一覧の検索・開閉・スクロールと設定のドラフトを残す。
- 設定は1列。項目名、入力する内容、説明を先に見せる。管理用キーと入力規則は詳細に置く。必須状態は一覧にも表示する。
- 型の設定では「編集する部分」で子項目へ移動できる。要件のまとまりでは子項目のボタンから移動できる。
- 同時表示が必要な利用者は「一覧と設定を並べる」を選べる。既存のペイン幅調整・保存設定を引き継ぐ。この選択で書類データやUndo履歴は変えない。
- 条件は左でノード追加または選択ノードの設定、右でキャンバス。設定からノード追加へ戻ってもキャンバスを作り直さない。
- HTML出力の選択要素用ツールは詳細に収め、未選択時の無効なツール群を最初から並べない。
- Wordの通常の差し込みは「入力項目を差し込む」から検索できるドックで直接行う。項目クリック1回で保持した本文のカーソル位置へ差し込む。項目名の差し込みも同じ欄で選べる。
- Wordのリボンはタブを切り替えても同じ高さとし、本文の位置を動かさない。ドックの検索で選択を失わず、入力が続くときに本文の編集DOMを交換しない。
- 大量の候補はスクロール可能な検索結果内に置く。くり返しの内側だけで選べる項目は、現在の編集位置に従う。
- 入力画面にはセクション移動を置き、再描画をせず目的の入力箇所へスクロールする。

## 操作

- 型と入力項目の一覧は名前・キーで絞り込む。入力項目は折りたたまれた子も検索し、祖先を残して表示する。
- 検索・幅変更・選択状態は書類データ、保存形式、Undoへ混入させない。
- 選択中は背景・太字・左のラインを併用する。単なる色の違いに依存しない。
- 項目一覧は Enter / Space でも選択できる。検索解除や再描画で編集位置を勝手に移さない。
- 右半分の作業領域とペイン幅の変更機能を維持する。集中表示は最初から1列とし、同時表示でも狭い設定欄は1列にする。
- 狭い画面では工程ナビを折りたたみ、明示的に開いたときだけドロワーとして表示する。Escape・外側のクリック・工程選択で閉じ、PC側の開閉設定は別に保持する。
- 視覚的な変化でDOMを再生成しない。既存の編集継続の基準は `docs/interaction-guidelines.md` に従う。
- 装飾用の絵文字や外部画像を操作アイコンとして使わない。動きは操作のフィードバックに限り、reduced-motionでは止める。

## 確認すること

通常版と持ち運び版で、型・要件・条件・出力・入力の各画面を確認する。PCの幅、狭い画面、ペイン幅変更、長い名前、多数の項目、入れ子、検索の解除、キーボードの選択、フォーカスの維持を通す。プレビューの文書書式にはUI用の文字サイズや色を適用しない。

新しい標準操作は `tests/task-flow-browser.cjs` で通常版・持ち運び版を独立したブラウザコンテキストで検証する。既存の詳細な機能試験は任意の同時表示を選んだ状態で実行し、両方の構成を維持する。画像も各工程で記録し、配置は画像と公開画面の両方で確認する。
