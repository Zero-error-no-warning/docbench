# 画面操作の統一：実装結果

対象はWordの出力設計、型定義、要件定義、条件定義、入力・書類作成。HTML・Excel・PowerPointの出力デザイナーは既存の機能と配置を維持した。

| 対象 | 実装した操作 |
| --- | --- |
| Word | 差し込み、繰り返し、表示条件、表、ページ、スタイル等を同じ右側パネルで操作。候補選択と実行を分離し、「差し込む」「適用」等で確定する。 |
| 型・要件・条件 | 画面全体を下書きとして編集し、共通の下端バーで反映／キャンセル。確定済み内容と下書きを分離し、移動・再読込で下書きを再開する。 |
| 試入力 | 型の確認、要件のフォームプレビュー、条件判定の試入力を実際の入力値から分離する。 |
| 条件 | グラフを主領域、ノードの設定を補助領域に配置。ノード追加は候補選択後の明示ボタン。検索・全体表示・ズームは設定中も使用できる。 |
| 入力 | 確定済みの定義で実データを直接編集・自動保存。項目検索、区分移動、エラー一覧から入力欄へ移動する。 |

Wordは上部ヘッダー44px、編集バー40px、下端ステータス28px。高さ720pxのPC画面で編集ペイン608px（約84%）を確保した。作業パネルは本文に隣接し、狭い画面では同じパネルを主領域へ切り替える。

定義の反映前には変更項目と入力値への影響を表示する。他画面で独立して更新された入力値は保持し、同じ内容が競合した場合は確定を止める。正式なJSON保存・履歴・出力には確定済みの内容を使う。

## 確認結果

- `npm run test:offline`：156件成功、失敗0。
- `tests/browser.cjs`：通常版・持ち運び版を通した操作が成功。ページの例外0。
- `tests/unified-workflows-browser.cjs`：未適用の分離、再読込、取消、試入力、明示的な差し込み、保持したカーソル位置、共通パネル、画面サイズ、入力時のフォーカスを確認。
- 既存の文字書式、表の結合・罫線、繰り返し行、条件、Word読込、保存・復元、Office出力、登録型・配列・階層選択、ペイン幅と並べ替えの回帰試験も成功。
- 通常版と持ち運び版は同じソースから生成。製品に実行時のネット接続や新しい外部依存は追加していない。

この実行環境ではCJKフォント描画時にChromiumがクラッシュするため、ブラウザー試験時だけフォントをserifへ置換した。置換は検証ランナーに限定し、製品ファイルには含めていない。標準フォントでのGitHub Actionsの試験は未実行。

## 試し方と公開状態

実装一式を展開し、`docbench/index.html`をブラウザーで開く。編集者画面へ切り替えるか、URL末尾に`#editor`を付ける。持ち運び版は`docbench/portable/docbench.html`。vendorフォルダーとの相対配置を維持する。

実装とローカルのコミットは完了。GitHubへの送信は自動承認審査が公開先への明示承認を確認できないとして拒否したため、公開版は未更新。承認後にリポジトリへ送信し、標準環境のCIを確認してから公開へ反映する。
