# 共通の操作基準

機能の追加・修正でも、ブラウザーの標準操作と編集中の位置を維持する。個々の画面の見た目とは独立した共通の要件とする。

- 入力値を変更しただけでは、別の入力欄・画面へフォーカスを移さない。階層選択も、選んだ欄に留める。
- クリック、Tab／Shift+Tab、日本語入力の変換中に、操作中のDOMを破棄しない。ブラウザーのフォーカス移動とネイティブ選択画面が完了してから必要な更新を行う。
- 再描画が必要な場合は、同じ書類・画面・項目の範囲で、フォーカス、選択範囲、未確定の入力、スクロール位置、選択中の操作タブを保持する。別の項目へ古い状態を適用しない。Undoや書類読込は、その操作が要求するモデルの状態を優先する。
- 配列・表への追加、複製、並べ替え、削除をマウスで実行しても、編集中の欄と選択範囲を保つ。値は操作前に保存し、行の不変IDで編集対象を追跡する。編集中の行を削除した場合のみ、近くの同じ欄へ戻す。キーボードでボタンを実行した場合はボタンへのフォーカスを維持する。
- モーダルは標準のdialog要素を使い、Tab移動を内部に保ち、Escapeで閉じる。閉じる操作で元の起点が再生成されていた場合も、対応する操作へ戻れるようにする。処理が明示的に編集位置を指定する場合は、それを優先する。
- ポップアップは画面内の利用可能な幅・高さに収める。左右端、下端、狭い画面、表示倍率の変化、親領域のスクロールを考慮し、必要なら上下を反転して内容側をスクロールする。
- 標準の文字編集・Undo、IME、ネイティブのselect・日付・色・ファイル選択を妨げない。専用操作が必要な場合だけ、その範囲でキー操作を定義する。

確認では、値や保存結果だけでなく、実際のpointerdown→blur/change→focus→pointerup/click、Tab、モーダルの開閉、再生成後の編集継続を通す。合成changeイベントだけのテストでは代用しない。IMEについては、変換開始・終了イベントを使ったDOM保持の検証と、実機での入力確認を区別する。

根拠となる標準・パターン：

- [WCAG 2.2：On Input](https://www.w3.org/WAI/WCAG22/Understanding/on-input)
- [WCAG：Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order)
- [WAI-ARIA APG：Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
